# INSERT

## Formas

```sql
-- Uma linha, com lista de colunas
INSERT INTO tabela (col1, col2) VALUES (v1, v2);

-- A partir de uma consulta
INSERT INTO tabela (col1, col2) SELECT a, b FROM outra WHERE ...;

-- [23ai+] Várias linhas num VALUES
INSERT INTO tabela (col1, col2) VALUES (1, 'a'), (2, 'b'), (3, 'c');
```

No 19c, várias linhas literais entram com `INSERT ... SELECT ... FROM dual UNION ALL ...` ou com `INSERT ALL` (tópico 02).

## Sempre com lista de colunas

`INSERT INTO tabela VALUES (...)` depende da **ordem** das colunas na tabela. Uma coluna nova, ou uma tabela recriada em outra ordem, faz o comando falhar (ORA-00947, ORA-00913) ou, pior, gravar valores na coluna errada quando os tipos são compatíveis. Em código que fica, liste as colunas.

## Valores padrão e colunas geradas

| Situação | Comportamento |
|---|---|
| Coluna omitida da lista | Recebe o `DEFAULT` da coluna, ou NULL se não houver |
| `VALUES (..., DEFAULT, ...)` | Usa o `DEFAULT` explicitamente |
| Coluna `GENERATED ALWAYS AS IDENTITY` | Não aceita valor informado (ORA-32795) |
| Coluna `GENERATED BY DEFAULT AS IDENTITY` | Gera quando omitida; aceita valor informado |
| `DEFAULT ON NULL` `[12c+]` | Usa o padrão até quando o valor informado é NULL |
| Coluna virtual | Não pode receber valor |

Para recuperar a chave gerada, `RETURNING ... INTO` (seção 02, tópico 12).

## Carga em volume

- `INSERT ... SELECT` numa instrução só é muito mais rápido que um `INSERT` por linha num laço.
- `INSERT /*+ APPEND */ INTO ... SELECT` faz **carga direta** (*direct-path*): grava acima da marca d'água da tabela, sem passar pelo cache de buffers e, se a tabela estiver em `NOLOGGING`, com geração mínima de redo. Em troca, bloqueia a tabela inteira até o commit, e a própria sessão não consegue ler a tabela antes do commit (ORA-12838).

## Armadilhas

- **Sem lista de colunas** (acima).
- **Conversão implícita** de texto para data ou número no `VALUES` depende do NLS da sessão (seção 03, tópico 06).
- **`INSERT ... SELECT` com `ORDER BY`** não garante nada sobre a ordem física das linhas; a ordem só existe numa consulta com `ORDER BY`.
