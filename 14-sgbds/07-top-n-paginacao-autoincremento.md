# Top-N, paginação e auto incremento

## Top-N e paginação

Os cinco maiores pedidos, e a segunda página de 20 linhas:

```sql
-- Oracle 12c+ e PostgreSQL (padrão SQL)
SELECT id_pedido, valor FROM pedidos ORDER BY valor DESC FETCH FIRST 5 ROWS ONLY;
SELECT id_pedido, valor FROM pedidos ORDER BY id_pedido OFFSET 20 ROWS FETCH NEXT 20 ROWS ONLY;

-- PostgreSQL e MySQL
SELECT id_pedido, valor FROM pedidos ORDER BY valor DESC LIMIT 5;
SELECT id_pedido, valor FROM pedidos ORDER BY id_pedido LIMIT 20 OFFSET 20;

-- SQL Server
SELECT TOP 5 id_pedido, valor FROM pedidos ORDER BY valor DESC;
SELECT id_pedido, valor FROM pedidos ORDER BY id_pedido OFFSET 20 ROWS FETCH NEXT 20 ROWS ONLY;

-- Oracle antes do 12c [legado]
SELECT * FROM (SELECT id_pedido, valor FROM pedidos ORDER BY valor DESC) WHERE ROWNUM <= 5;
```

| | Oracle | PostgreSQL | SQL Server | MySQL |
|---|---|---|---|---|
| `FETCH FIRST n ROWS ONLY` | 12c+ | Sim | Só com `OFFSET` antes (2012+) | Não |
| `LIMIT n OFFSET m` | Não | Sim | Não | Sim |
| `TOP n` | Não | Não | Sim | Não |
| Empates (`WITH TIES`) | `FETCH FIRST 5 ROWS WITH TIES` | `FETCH FIRST 5 ROWS WITH TIES` (13+) | `TOP 5 WITH TIES` | Não (usar `RANK()`) |
| Porcentagem | `FETCH FIRST 10 PERCENT ROWS ONLY` | Não | `TOP 10 PERCENT` | Não |
| `ORDER BY` obrigatório | Não, mas sem ele o resultado é arbitrário | Idem | Obrigatório para `OFFSET` | Idem |

Top-N **por grupo** (o maior pedido de cada cliente) é igual nos quatro: `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` numa subconsulta (seção 05, tópico 07). MySQL só a partir do 8.0.

### OFFSET em páginas distantes

`OFFSET 100000` lê e descarta 100 mil linhas para devolver as 20 seguintes, em qualquer um dos quatro bancos. Para paginação profunda (exportação, API com rolagem), use **paginação por chave** (*keyset*): guarde a última chave da página e peça as seguintes:

```sql
SELECT id_pedido, valor FROM pedidos WHERE id_pedido > :ultimo_id ORDER BY id_pedido FETCH FIRST 20 ROWS ONLY;
```

Com índice na chave, cada página custa o mesmo, da primeira à milésima.

## Auto incremento

| | Oracle | PostgreSQL | SQL Server | MySQL |
|---|---|---|---|---|
| Coluna de identidade | `GENERATED ALWAYS AS IDENTITY` `[12c+]` | `GENERATED ALWAYS AS IDENTITY` (10+); `SERIAL` `[legado]` | `IDENTITY(1,1)` | `AUTO_INCREMENT` |
| Sequence independente | `CREATE SEQUENCE`, `seq.NEXTVAL` | `CREATE SEQUENCE`, `nextval('seq')` | `CREATE SEQUENCE` (2012+), `NEXT VALUE FOR seq` | Não há |
| Obter o valor gerado | `INSERT ... RETURNING id INTO :v` | `INSERT ... RETURNING id` | `OUTPUT INSERTED.id` ou `SCOPE_IDENTITY()` | `LAST_INSERT_ID()` |
| Valor como padrão de coluna | `DEFAULT seq.NEXTVAL` `[12c+]` | `DEFAULT nextval('seq')` | `DEFAULT NEXT VALUE FOR seq` | — |
| Inserir valor explícito | `GENERATED BY DEFAULT` em vez de `ALWAYS` | `OVERRIDING SYSTEM VALUE` ou `BY DEFAULT` | `SET IDENTITY_INSERT tabela ON` | Basta informar o valor |

Antes do 12c, o Oracle não tinha identidade: o padrão era sequence + trigger `BEFORE INSERT` (`:NEW.id := seq.NEXTVAL`). Ainda aparece muito em código existente.

Cuidados que valem para todos:

- **Haverá buracos.** Rollback, cache de sequence e reinício da instância consomem números. Número sequencial **sem buracos** (nota fiscal, por exemplo) precisa de uma tabela de controle travada na transação, não de sequence.
- No SQL Server, `@@IDENTITY` devolve o último valor gerado na sessão **inclusive por triggers**; `SCOPE_IDENTITY()` devolve o do próprio comando. Use o segundo (ou `OUTPUT`).
- No MySQL, `LAST_INSERT_ID()` de um `INSERT` de várias linhas devolve o **primeiro** id gerado.
